# Vampire Saved — the port's own discipline (level 2, this project only)

Agent-facing rules, IDs `[VSP-NN]`, each ANCHORED `**[VSP-NN]**` at the
paragraph it distils in `CLAUDE.md`, `HANDOFF.md`, `docs/project/*.md`,
`docs/game/gotchas.md` or the two standing sections of `STATE.md`, locked by
`tools/checkskills.py`. **CLAUDE.md is the law and this skill is the
reminder**: rules in D.1 cite it by section and add nothing. Everything
else here is a way the pipeline, a gate or a rig produced a confident wrong
answer, and the check that stops it from happening again. Facts about the
game are `[VSE-NN]`, about the emulators `[CPE-NN]`, about the board
`[CPH-NN]`, about the FPGA lane `[MSC-NN]`/`[MSV-NN]`.

## D.1 The law, by citation (CLAUDE.md and the two standing STATE sections)

- [VSP-1] **THE SUPERSET INVARIANT (CLAUDE.md §1)** — every path not involving the three new characters produces frame-identical RAM to vanilla under identical inputs. A change that improves a tenant and perturbs one legacy byte is a FAILED change, not a trade-off.
- [VSP-2] **Rule 1 v2 (§2.1)** — emulator cores are never modified outside the ratified CPS-2 WIDE profile ([CPH-29]); the profile's two gated blocks in `Cps2ObjDraw` are the whole exception. Anything else that "requires" touching CPU/sprite/timing/QSound code is stop-and-escalate: write it up in STATE, do not write it in the core.
- [VSP-3] **Rule 2 (§2.2)** — no untested change survives a session; "it should be equivalent" is not a test result. Every patch, however trivial, goes through the harness before it is committed.
- [VSP-4] **Rule 3 (§2.3)** — no hand-edited binaries. Output bytes come from `build/manifest/*.toml` + sources + extracted tables, and the tree must reproduce the set from pristine inputs at any commit (`test_m3a_reproducible.sh` is that claim, run on every machinery commit).
- [VSP-5] **Rule 4 (§2.4)** — every byte range is tagged VSAV / VS2 / VH2 / GEN / NEW and the atlas is updated in the SAME commit as the change that moves provenance.
- [VSP-6] **Rule 5 (§2.5)** — anything that defines how a ported character plays lives in the documented tables of `docs/project/tables/`, never as a constant in code.
- [VSP-7] **Rule 6 (§2.6)** — a diverging regression suite halts forward work; fixing it is the only task until green.
- [VSP-8] **Rule 7 (§2.7)** — no ROM bytes in the repo or any artifact, in any form, including excerpts pasted into docs. Rendered frames (the PNG goldens) are derived work and exempt by ruling; ROM BYTES are not, ever.
- [VSP-9] **The reference sets (§3)** — `vsavj` (Japan 970519, DECIDED, do not reopen), `vsav2`, `vhunt2` live outside the tree in `$ROMDIR`; verify their SHA-1 against `docs/checksums.txt` before any session that reads them, and stop on a mismatch. Analysis scripts take the ROM path as an argument and print the SHA-1 of what they read.
- [VSP-10] **Gameplay decisions are not yours (§5)** — anything a player could feel goes to STATE "Decisions pending" with options and a recommendation; continue on unblocked work. Mark rulings DECIDED in place when they arrive.
- [VSP-11] **Address notation (§5)** — `PRG:0x0F1234`, `CPU:$0F1234`, `GFX:tile 0x1A2B3`, `RAM:$FF8000`; never bare hex without a namespace.
- [VSP-12] **File by the FACT (§5)** — `docs/game/` (true if the hack were abandoned), `docs/platform/` (the board and emulators), `docs/project/` (this port). Findings land in the right document at discovery time, not at milestone end.
- [VSP-13] **RETRACTION DISCIPLINE (§5, standing order 14z-71)** — when a claim changes, `grep -rn` its WORDING and paraphrases across `docs HANDOFF.md STATE.md STATE_HISTORY.md DECISIONS_HISTORY.md tests build/manifest`; fix the HEADER and summary line first; keep the superseded analysis marked RETRACTED with what replaced it and the correcting session named; re-grep and show the empty result. A stale header is worse than no documentation.
- [VSP-14] **BUG ARCHAEOLOGY FIRST (§5, standing order 14z-75)** — before theorising about a reported defect: `git log --grep`, `git log -S` on the manifest row, grep STATE_HISTORY for the symptom; find the last-known-good build and diff it against its predecessor; if the record is ambiguous about whether it was ever fixed, ASK the maintainer. Wrong in both directions is expensive.
- [VSP-15] **Anti-hyperfocus checkpoint (§5)** — at a confirmed finding, a green suite or ~20 tool iterations on one problem, stop unprompted: update the docs, capture scratch tests into the suite, reassess the approach, check STATE for drift.
- [VSP-16] **Build conventions (§5)** — builders are Python taking `(src, out)` so they chain onto any input; every tunable is a builder flag, never a hex edit; bundles chain builders then diff ONCE against clean (never chained standalone binary patches); shipped builds carry the visible version mark; every build's SHA-1 goes in the registry.
- [VSP-162] **The `14z-N` session tag is the archive's LOOKUP KEY (§5)** — one SESSION (a context window, ~several a day), not a day, a milestone (`M0`..`M12`) or a freeze mark (`donovan-m18`). **`14z-` is a FOSSILISED PREFIX — one opaque token; the live counter is `-N`, and nobody is "in session 14".** Letter suffix = a continuation, `(n)` = a phase within the sitting. NEVER rename, renumber or tidy one: gate headers, tag messages, `patch_notes.md`, gotcha datelines and THE LEDGER are pointers into it, and section names survive every rollover so the key keeps resolving. Origin and the limit of the search that established it are in §5 — do not re-derive them.
- [VSP-17] **The session ritual (§5)** — begin by reading STATE (after CLAUDE.md, then HANDOFF, then NEXT_SESSION); end by updating STATE, rewriting NEXT_SESSION as a 60-second orientation, and rolling the oldest of the ~3 session groups VERBATIM into STATE_HISTORY with its LEDGER line. Archived entries are never rewritten; corrections are marked in place.
- [VSP-18] **THE PERSISTENT SUITE DOCTRINE (§4)** — every in-emulator measurement, probe or verification run during development is captured as a rerunnable case under `tests/` before the session ends. No throwaway manual checks; the suite only grows.
- [VSP-19] **Verdict logic is itself tested (§4)** — a classifier's verdicts are validated against ground-truth scenarios before they are trusted, in BOTH directions; a gate born against a live defect has never exercised PASS, so its first green is read by its printed values, not its verdict word.
- [VSP-20] **FIELD REPORTS ARE RECORDINGS (§4, maintainer-ruled 14z-111)** — every reproducible crash a human can produce is captured FIRST as a hand-played MAME `.inp` (`WIDE_RECORD=<name> tools/run_wide.sh <build> mame`), named `<what>-<freeze set>-NN` for the freeze it was PLAYED on, tracked under `tests/inp/<name>/` with a one-line NOTE, replayed by `tools/run_inp_guarded.sh` (the game's own `$FF0000` exception store, no debugger) and by `tests/test_inp_corpus.sh` at every freeze. The cache copy is deleted once tracked; an unreferenced recording is deleted, not kept. Three sessions and two shipped fixes were spent on a rig-derived mechanism that was never the field crash.
- [VSP-21] **STANDING PRINCIPLE: vanilla wins ties (maintainer, 2026-08-05)** — when a console port and arcade vsav differ and both would work, take vanilla. A port's choice is evidence of its designers' preference, not that vanilla is wrong; the test is "does keeping vanilla still let the feature work?"
- [VSP-22] **THE DEADNESS REGISTER's rule for a row** — a claim of the form "legacy never reaches this, so we may reuse it" is measured by ABSENCE, the weakest evidence accepted here, so it needs a POSITIVE CONTROL on the same instrument and leg, a named guard, and a stated fallback if wrong. Prefer designs where being wrong is SAFE AND LOUD (the type-6 fallback held when its deadness claim turned out false) over designs that are merely well-measured.
- [VSP-23] **The register is the FIRST place to look** for any unexplained regression in vanilla assets, engine behaviour or rendering — before anything else is suspected; its withdrawn rows show the claim class does fail.

## D.2 Oracles and frozen expectations — what a class is, and what may never loosen one

- [VSP-24] **Which emulator runs which oracle (§4, corrected GitHub #78)** — MAME is the per-frame whole-corpus legacy oracle (the frozen `.masked` classes); FBNeo carries the emulator superset invariant on pristine `vsavj` (`test_wide_profile.sh`, reference vs patched binary), dual-track inertness on one binary (`test_dualtrack.sh`), and a SAMPLED hacked-vs-vanilla legacy check (`test_fbneo_legacy_oracle.sh`). The full FBNeo legacy track is accepted-and-deferred to a third implementation.
- [VSP-25] **Dual-track inertness means bit-identical UP TO SELECT ENTRY (ratified 14z-94, #95)** — the stock and WIDE builds carry different rosters by construction, so every select-reaching replay must differ; onsets are frozen per replay and an onset moving EARLIER is the failure.
- [VSP-26] **The two FBNeo-only phase classes are FROZEN INVENTORIES, not windows (ratified 2026-08-16, #78)** — the sound work area `$FF0500-$FF05FF` and the OBJ-builder secondary stack `$FF06D0-$FF06EF` may differ on FBNeo where MAME shows none, but a byte inside a window and OUTSIDE the measured offset inventory FAILS as growth; `FBNEO_ORACLE_EXPECT=exact` is available to anyone who wants bit-identity.
- [VSP-27] **Hooked-build legacy comparison is live RAM under exactly the named masks (`docs/project/oracle_classes.md` v1/v2, CLAUDE.md §4's spec of record)** — the dead-stack window `$FF7F00-$FF7FFF` and the QSound latch `$FF043C`; on that basis the classes are exact (default), flicker-tolerated (isolated ≤2-frame divergences, ≥60-frame re-convergence, ≤8 divergent frames, `compare_flicker.py`), and frozen first-divergence constant. A replay may not be reclassified to a looser class without a new measured mechanism AND maintainer sign-off.
- [VSP-28] **The bounded re-convergent window (`oracle_classes.md` v3) needs all four, frozen per replay** — one CONTIGUOUS divergent run, a fixed ONSET, full RE-CONVERGENCE to bit-identical, and match state untouched; introduced for the select wheel's three added cells and STRICTER than the first-divergence constant. Checker `tools/compare_window.py`, ground-truthed by `tests/test_compare_window.sh`.
- [VSP-29] **Composite (`oracle_classes.md` v4) is the strict CONJUNCTION of flicker and window and adds NO tolerance** — every divergent run accounted for by name, the flicker set equal to its frozen inventory, the window list exact, full re-convergence; a bit-identical pair FAILS it. `tools/compare_composite.py` / `tests/test_compare_composite.sh`.
- [VSP-30] **The ≥60-frame rule is INTRA-MECHANISM (`oracle_classes.md` v5, maintainer-ruled)** — it governs the tail after the last divergence of ONE mechanism and does not bind across the gap between two separately attributed ones; `--min-converge-flicker` stays default-off and the two named palette-fade exemptions are recorded against the day it is turned on. A third exemption means measure the real minimum, not lengthen the list.
- [VSP-31] **THE STANDING WATCH (maintainer, 2026-07-27)** — flickers growing beyond the frozen inventory or divergences turning systematic mean STOP AND ROOT-CAUSE; that pattern is a deeper issue, never tolerance noise. Whole-RAM frame-exact remains the standard for vanilla oracles, determinism and hook-free builds.
- [VSP-32] **Dual-emulator agreement for tenant content (§4)** — patched FBNeo and patched MAME must agree on the MAPPED fields of `ram.md` at sync anchors (match start, round transitions), not on whole-RAM checksums; the emulators traverse identical states on different frame indices after boot.
- [VSP-33] **Test-matrix growth and the edge-case bias (§4)** — every new capability adds replays (per ported character: vs each of the 18 both sides, every stage, Dark Force on/off, life marker, timeout, throw/tech, pursuit); prefer pathological inputs — bugs live at state transitions.
- [VSP-34] **A masked window is a BASIS, not a flag** — `replay.lua` skips masked bytes from the checksummed stream, so adding a window changes every frame's checksum: the vanilla masked logs are REGENERATED under the new mask into a new basis dir (`tools/freeze_masked_basis.sh`), every `.masked` spec re-based, and every gate hard-coding the base path or `MASK_RANGES` updated (grep `masked-v`).
- [VSP-35] **Palette CONTENT in a fade's row set is CYCLE-relevant** — data-only is not cycle-neutral; the select→VS fade runs at the VBL edge and a recoloured processed row cost a legacy pairing one main-loop iteration, never re-converging. Before moving or recolouring any select palette row, run the legacy pairings against vanilla (not just the masked 13) and attribute moved `.sha1`s with `tests/audit_mask_window_ff42a2.sh`.
- [VSP-36] **A self-frozen `.sha1` cannot see a legacy regression** — it answers "did this build change since I froze it", and re-freezing makes any behaviour correct by definition; only a `.masked` spec compares against vanilla. Classify replays by MEASUREMENT (the `+0x60` hitbox-base signature, distinct-value sequence not frame-indexed trajectory), never by filename or authoring intent — `tests/audit_legacy_pairings.sh` fails a legacy pairing guarded only by a self-frozen expectation.
- [VSP-37] **A comparator's own ground-truth test can RATIFY a deviation from the ratified text** — three artifacts agreeing with each other looks like validation; check the comparator against CLAUDE.md §4's wording, and scope any "unmeasurable" claim to the instrument that governs it (19 flicker specs, tails a `wc -l` away).
- [VSP-38] **Moving a frozen ONSET frame can silently cross a verification-class boundary** — an onset shift of one frame re-dated ~30 composite specs into a stricter class; re-classify by measurement when an onset moves, never by editing the number.
- [VSP-39] **A hook on a hot shared path can flip a frame-boundary parity PERMANENTLY** — flicker's evil twin: a marginal same-frame multi-writer field locked to the other side of a VBL from added cycles. Before thunking a site, census its CALLER SET across all screens; review late-replay tails, not just known windows; treat a one-frame flicker in the inventory as a tripwire for added cycles.
- [VSP-40] **Build in one step, measure in another — never in one command** — a chained rebuild+check gave two contradictory verdicts on one image and one of them was committed as a finding. Re-run before believing a gate that contradicts a previous green; if the text you are writing disagrees with the last tool output, stop.
- [VSP-41] **Engine hooks break whole-RAM comparison BY CONSTRUCTION** — a hook on a path vanilla executes costs cycles, interrupts land at skewed boundaries, and dead-stack ghosts plus a one-frame latch phase appear on otherwise-vanilla content; the ghost-clean topology (patch only the `movea/moqeq` to `jmp thunk`, keep the vanilla `jsr` at its address) removes the return-address source and nothing removes the skew — zero-cycle extension is impossible here.
- [VSP-42] **GFX and coordinate data are INVISIBLE to every RAM-basis gate** — tile ROM content, scroll/OBJ byte sharing, and ROM→OBJ coordinate lists never transit work RAM, while cached list POINTERS do; the pixel gate (`test_gfx_menus.sh`) detects the first class and the masked gate the last, and it takes BOTH to make pool surgery safe. Never change a host record's cptr; never write pool bytes another consumer shares.
- [VSP-43] **The RAM gate cannot see NEW-CHARACTER visual wrongness** — masked gates cover legacy content, the oracle compares mapped fields, the pixel gate covers menus: any change touching the effect/display path ships with a before/after `SNAP_FRAMES` pixel A/B on a replay that exercises it, and no object field is declared dead by RAM alone.
- [VSP-44] **Sound and anything leaving the 68k address space needs its own detector** ([CPE-36]) — `tests/test_don_sound.sh` exists because every RAM and pixel gate was green while a tenant was silent, and equally green when a path played MUSIC ids; the per-node sfx helper and its record array are enabled by ONE manifest field (`unstub` on the `[[sound_table]]` row) so they cannot be enabled separately.

## D.3 Extraction, reconciliation and generation — the law of the pipeline

- [VSP-45] **Sibling-coincident engine refs are INVISIBLE to the diff oracle, and the coincident vsavj address is usually a WRONG routine** — `extract_char.py` merges scanner-LABELED operands (jsr/jmp/pea/lea/movea/move_src, never bare longs) into every twinned region's ref list; identity rows are legal only with byte-verified identical targets; farm entries resolve by save+sfx-id signature; a no-exception display freeze is diagnosed by VIDEO-HASH BISECTION.
- [VSP-46] **Bare-long "pointers" in 68k code are usually OPERAND PAIRS** — sibling-veto every candidate (a real pointer differs by the host region's sibling shift, operand bytes are identical); conflicting or absent evidence REJECTS loudly, never rewrites silently; immediates are refs only when they land inside a ported region.
- [VSP-47] **PC-relative word tables are DATA** — record every discovered table's full extent, exclude it from the relocation heuristic, bound its length by the smallest forward displacement, and keep table-referencing regions in a `[[layout_group]]` so source-relative spacing survives.
- [VSP-48] **Blind long relocation over data blobs corrupts streams** — for a MIXED zone the rewrite set comes from a STRUCTURAL CLOSURE walk (tables → strips → streams → records), never a flat scan; the narrow-window + record-validation approach holds only where the pointer web is known.
- [VSP-49] **Never write an unverified gap** — a gap between known tables is not a table row; no write without a decoded consumer. Restore-bisection (vanilla bytes over patched spans) attributes engine deltas, hardened with a liveness check because spans cutting executing ported code read as false "fixed". Verify the per-char-row + dark-mirror assumption PER TABLE.
- [VSP-50] **Disabling a heuristic CLASS wholesale reverts load-bearing writes** — enumerate what the class actually wrote and re-port its load-bearing members explicitly; build-timeline correlation is attribution, only a mechanism trace convicts; a play-sampled "fixed" is weaker than a replay trace.
- [VSP-51] **Early generic rows can masquerade over later-understood structures** — when a structure class becomes understood (farm, dispatch bank), re-audit every earlier generic row whose source address falls in its range; match MECHANISM, not row kind.
- [VSP-52] **Sibling twins can differ by ONE hoisted instruction** — when a source ref lands a few bytes past a routine head, check what the skipped bytes DO; "wrong data, right table" presents as plausible behaviour invisible to RAM and crash gates; reconciliation kind `patched_clone` is the fix.
- [VSP-53] **Fuzzy code-similarity reconciliation collapses near-identical helpers** — for helper families the identity that matters is the PARAMETER (table content + dispatcher kind), content-verified; `farm_port` (port table + stub) is the fallback when no exact twin exists.
- [VSP-54] **Twin sites are paired through the DISPATCH TABLE, never by byte pattern** — decode both engines' per-seq jump tables and pair by row index; and before porting any per-char handler entry, check whether the target table's tenant row is ALREADY repointed on the built image.
- [VSP-55] **A single-shift sibling scan dies at the newcomer window's PIECEWISE structure** — group dispatch targets by their own pair delta first; never classify refs inside a tolerated filler run; a boundary probe must require the instruction-start opcode word to MATCH.
- [VSP-56] **A window constant is a census, not a fact** — the newcomer-code window was Donovan-era triage and mis-classified thirteen of Huitzil's rows as veteran aliases; re-derive per tenant, and compare the SOURCE game's per-char row against its alias row even when every target is engine space.
- [VSP-57] **CODE-region ref fields are word-aligned by ISA; an idempotence latch on a pool-head is false mid-match** — the classifier enforces even offsets under `allow_engine`, and a robust one-shot latch is phase-gated or a dedicated byte.
- [VSP-58] **A SET-NAME MISMATCH IS A FALSE GREEN** — when a build's pack flips to `vsavjw`, any probe still run with `SET=vsavj` boots the PRISTINE ROM from `$ROMDIR` and soaks "clean"; every gate derives the set from the rompath contents, and a suspiciously clean result after a build-shape change is a prompt to verify WHAT ROM ran.
- [VSP-59] **PC-relative escapes in engine-style regions are INVISIBLE to the sibling oracle and unrewritable in place** — `[[pcrel_escape_fix]]` reserves an adjacent trampoline pad and bounces each escape through `jmp <twin>.l`; run its census on EVERY engine-style region.
- [VSP-60] **A tenant porting SHARED regions inherits every region-scoped mechanism row those regions carry** — diff the other tenants' manifests for every row scoped to the region and copy them BEFORE the first probe run; the crashes are pre-paid knowledge.
- [VSP-61] **A `port_patch` on a shared engine-family region fixes ONE tenant's copy** — when a new tenant imports a region, `grep 'region = "<name>"' build/manifest/*.toml` and bring its rows; and do NOT blanket-copy the stage-99 parked families whose ported READERS consume vars at source offsets.
- [VSP-62] **The four checks before rooting a code region** — bound by the sibling oracle then check what it cut (`:f` forces plain-value tables only); census the pc-relative DATA tables (indexed AND post-increment shapes); census the pc-relative BRANCH escapes; check the span contains the CONSTANTS its own code loads (disassemble BACKWARD from the first instruction).
- [VSP-63] **Crypt placement: the opcode view executes, the data view is garbage** — a region below `PRG:0x100000` is stored re-encrypted; a table inside it that is read as data must be emitted RAW (`:fN` splits at the FIRST table, not the oracle boundary) or relocated through `[[data_in_code]]`. Moving a whole code region to raw space does NOT fix an embedded table (one byte image, opcode view).
- [VSP-64] **Put an execution breakpoint on code before attributing a symptom to it** — co-location is not causation; a region with genuinely broken tables was not the region whose code ran in the scenario.
- [VSP-65] **A ported region must CONTAIN its constants and its tables** — pc-relative data pointers are copied verbatim and resolve to `target + delta`, correct only if those bytes travelled; a separate root for the table does not work; `tools/verify_pcrel_data.py` decides on the BUILT image (compare DATA views). Re-verify the twin delta at a NEW root start.
- [VSP-66] **A dead-filler classifier comparing the OPCODE view is blind to DATA** — if the siblings' DATA views of a candidate filler run are byte-identical, it is data; and `census_regions.py` must not treat `lea (An,Xn),An` as a redefinition.
- [VSP-67] **`placements.json` is a LINEAR map but the extractor auto-discovers sub-region shifts** — CORRELATE (slide the candidate source, take the offset with the most matching bytes) before reading a sub-90% figure as corruption; ~85% with every mismatch a pointer field is what "correctly ported" looks like.
- [VSP-68] **A built-image walk VERIFIES the source's structure; it never re-derives it** — a pointer-shaped heuristic is placement-dependent (an unrelocated longword that happens to land in the placement window validates a phantom record); both walker passes take the source's accepted offsets and `ptr_allow` requires the target to match; any allocator growth re-rolls the dice, so "it was green before" is not evidence.
- [VSP-69] **Every TYPE/CLASS byte in a ported record indexes some engine dispatch, and the engines RENUMBERED families** — enumerate EVERY dispatcher the byte reaches (not the first found), validate each ported byte against vsavj's bounds at BUILD time with a family-aware census (`tools/audit_fsm_census.py`, never a blanket byte scan), and remember a dispatcher-exact remap can still change gameplay through stored-class property lookups.
- [VSP-70] **"Entry N" past the end of a word-displacement jump table is the NEXT routine's OPERAND** — compute the entry count `(first_code_addr − table_base) / 2` and refuse any index ≥ it; a "0 reads" deadness check proves nothing unless the replay set exercises the code around the address.
- [VSP-71] **"16 + the same 16 repeated" is a silent tenant trap** — an aliasing guard never faults, it plays another character's data ([VSE-12]); when a tenant misbehaves ONLY under CPU control, audit every `stride 0x80` table for PARKED rows, and give a CPU-behaviour soak TIME, not hits.
- [VSP-72] **Hole "a" is inside the crypt range; thunks with EMBEDDED DATA go to hole "b"** — placed bytes plaintext in-zip means outside the crypt range, garbled means inside; any `site_thunk` whose body is read as data takes `hole = "b"`.
- [VSP-73] **A slot id or a PLACED ADDRESS baked into hand-authored `thunk_hex` tracks NOTHING** — use `TT` for the tenant id and `region_subst` for addresses; a literal id compared against `$FF8782`/`$FF8B82` that mismatches the tenant FAILS the build (`tests/test_thunk_addr_literal.sh`); grep the ENCODED form (`000f`, `#$0f`) as well as the source form; when a stale value is identical on two builds, grep for the VALUE before tracing the code.
- [VSP-74] **The manifest subset: no dotted table names, no arrays** — `_minitoml` and `tomllib` parse them differently per host, which made a fix row never apply on this machine; encode nested structure FLAT (`fixes = "off:old:new,..."`, comma-separated strings) and let the generator hard-fail on orphan dotted keys.
- [VSP-75] **Descriptor CRCs for variable-content members are SENTINELS** — a real member's CRC or the fill member's CRC resolves BY HASH onto something in the search path (a zero QSound member loaded silent zeros); sentinels match nothing so the member always resolves by NAME; `-verifyroms` reporting them bad is the honest cost, and it cannot be a liveness check on this project's sets.
- [VSP-76] **An output dir that different modes populate differently is cleaned per build** — stale members were re-packed by a glob for a generation; group-C mode ASSERTS group B pristine in the packed zip. "The file exists" says nothing about which build wrote it.
- [VSP-77] **Exactly one writer per WORD** — `patch_prg.py` hard-fails on overlap naming both ops (`tests/test_patch_overlap.sh`); a section that pokes a table row claims it explicitly rather than relying on emission order; overlap granularity is the word because odd-aligned pokes merge pristine neighbour bytes; a measured section owns a row over a triage tag.
- [VSP-78] **The tile-placement pool is block-aware first-fit — carving cells out CASCADES the allocation** — fixed-position tile needs allocate at the pool TAIL or ride the existing exception flow; a mid-run reservation moved hundreds of placements and desynchronised every frozen artifact that referenced cells.
- [VSP-79] **"Inside the placed band window" is NOT "overwritten"** — the placement inside the bound is SPARSE; decide survival by intersecting with the ACTUAL placed tile set or by measuring pixels; the window exonerates only when the intersection is EMPTY.
- [VSP-80] **In-place substitution has invisible slot dependencies** — every per-slot value the host already had RIGHT becomes a defect when the tenant moves off the slot; the de-substitution acceptance (bounded window, gate section 4) is the behavioural net and RAM-diff-at-frame names each culprit's subsystem.
- [VSP-81] **A record's BANK is a property of the DRAWING OBJECT, not of the record** — attribute by breakpointing the OBJ format handlers and reading `+0x18(A6)` live, then close the set STRUCTURALLY from the sub-object's own record stream, never from a global scan or content voting.
- [VSP-82] **The A5-relative work-var displacements differ between engines** — a ported damage applier staging into vs2's offsets ticks, combos and sparks correctly while HP never moves; the same-value class is reconciled per tenant copy (see [VSP-61]).
- [VSP-83] **A ported region whose consumers index NEGATIVELY needs headroom below its base** — never allocate it at the bottom of `wide_ext`, whose first bytes sit against the reserved register window; an address error on an ODD address is a louder signal than "wrong data" and is read as such.
- [VSP-84] **Route objects to a ported machine on facts baked at BUILD time** — dispatch-time owner reads are transient at spawn instants (recycled slots, the type byte rewritten within the spawn frame); use spawn-time tags and per-tenant type numbers, never runtime state near a spawn.
- [VSP-85] **The discriminator for a ported machine is PER-EFFECT, not per-hit or per-character** — a stamp at a victim-spawn site serving every hit routed Dark Force's objects into the wrong machine; run `test_hui_pairs` on any change that routes objects, not only the gates for the move being fixed.
- [VSP-86] **An "owner-gated" thunk on a shared routine is not scoped by owner alone** — sibling effect families share subtypes, so enumerate every family of the tenant's OWN content that reaches the site; base, stream, count and updater are ONE unit — port the region or nothing.
- [VSP-87] **Per-char dispatch on a COMMON seq state needs the target flow's FULL closure first, and a "cold" site can be legacy-hot** — an owner-gated thunk there costs legacy cycles and breaks masked-EXACT legs; run `tests/test_hui_boot.sh` after ANY `site_thunk` addition, and verify a park/comment edit actually changed the file.
- [VSP-88] **A stamp census must enumerate WRITE FORMS** — the `move.b #imm,(d16,An)` form hid ~26 stamp sites behind a one-form scan; `tools/audit_type_stamps.py` carries a positive control, `tests/audit_type_writes.sh` maps every observed family write to a frozen row, and d16 distinguishes the type field from the owner byte.
- [VSP-89] **Sampled uniformity is not uniformity** — disassemble ALL N sibling cases and diff them before synthesising N parallel engine cases; add a build-time assertion against the source engine's own table so config drift fails the build (8 of 12 synthesized stubs were wrong).
- [VSP-90] **"Run once at match start" is a TIMING TRAP** — char-init, the first per-frame tick and `$FF8004` all fire during the VS screen; arm a counter at init and act at zero while match-active, in the object-UPDATE phase so the same frame's list rebuild hides it.
- [VSP-91] **A 0x7xx sfx id's faithfulness is a property of its CONTENT, not its number** — before a `stubbed_sound` row or a sample-port plan, CONTENT-SEARCH vsav's QSound image for the vs2 keyon's window (inclusive endpoint included) and check `keyons_vsavj` at the hit; attribute the CALL PATH before the record.
- [VSP-92] **The tenant manifest's slot-row vocabulary is how a row states its tenant behaviour** — `[[tenant]]` normalises into the legacy `[port]` shape and drives gfx through `patch/tenant.json`; `recon_overlay` belongs INSIDE `[[tenant]]` (at doc root it goes GLOBAL on a merged build and kills another tenant's rows); rehearse every staged recipe on the MERGED composition, and stage value swaps as an edit instruction, never a duplicate key.
- [VSP-93] **The hardening register is maintained in the SAME commit as any change to its classes** — the rule-4 partition (VANILLA / PATCHED / RAM / PATCHED-TRIPWIRE / HW / SENTINEL / WIDE-HOLE) is frozen by `tests/test_pointer_flow.sh`; STRONG findings are reviewed individually before freezing, WEAK ones frozen by COUNT so growth fails; score is not risk — CONSUMPTION is.

## D.4 Freezes, registry, build directories, releases and the suite

- [VSP-94] **Every frozen build is git-tagged `freeze/<name>`** (annotated, fingerprint + reproduction in the message) and gets a registry row in HANDOFF; the tag is the only way back for a superseded build whose manifests moved on; the stock twin is rebuilt at every freeze and its fingerprint stated as MOVED or UNCHANGED with the reason.
- [VSP-95] **A profile bump invalidates every frozen build as a REFERENCE (not as a record), and a re-freeze re-points every gate that names a build by path** — grep the suite for the OLD directory name; a path-named default is a dated assertion with no expiry (`test_build_ref_rot.sh` reports currency); sort references by "does it BOOT?" when triaging; a comparator must report a missing operand as a DEAD LEG, never compare it.
- [VSP-96] **Build-dir policy: keep CURRENT + ONE BACK per track, and before deleting grep FOUR places** — `tests/` and `tools/` excluding comment lines, `build/manifest/` (a `build = "build/don_m7"` row turned a gate into a SKIP), `docs/` read for intent, and the freeze policy itself; run `run_all_static.sh --strict` BEFORE committing the deletion, because it is the only instrument that catches a gate degrading to SKIP.
- [VSP-97] **"Tracked" build dirs are only PARTLY tracked** — a gate whose fixture is an old build dir depends on UNTRACKED generator outputs; restoring one means a historical rebuild from its freeze commit in a worktree, and re-pointing the gate at a current build is REFUSED when it would launder an unreviewed inventory into the gate that exists to review it.
- [VSP-98] **Recordings: tracked the moment they have a consumer, deleted the moment they have none** — `grep -rn <name> tests tools docs HANDOFF.md STATE.md CLAUDE.md` empty means delete; the cache original is deleted once tracked (see [VSP-20]).
- [VSP-99] **`patch_index.md` is the REGISTRY, updated in the same commit as any patch change** — status, dependencies, exclusivity, deprecation; byte detail lives in `patch_notes.md` (newest first) and each build's generated `patch/patch_notes_fragment.md`; mechanism rationale in the manifests' inline session tags.
- [VSP-100] **A release is ONE DIRECTORY PER PLATFORM, each self-sufficient, with no ROM bytes** — `release/<name>/{fbneo,mame,mister}/` from `tools/package_release_platforms.py`: xdelta deltas against the reference dumps' members, `manifest.json`, the community applier that refuses to write unless EVERY member's sha1 matches; the bitstream is a BUILD RESOURCE at `release/bitstreams/<seed>/` named by `CURRENT`, hash-verified in and never copied from another release ([MSV-16]); `tests/test_release_roundtrip.sh` round-trips it and scans for reference-ROM chunks.
- [VSP-101] **THE PRE-COMMIT COMMAND is `tests/run_all_static.sh`, not a filename** — the portable tier is ROM-free (~1 min), `ROMDIR=...` adds the static tier, `--strict` makes SKIP fatal; it reports PASS / SKIP / FAIL separately because SKIP IS NOT PASS, and its registry-coverage check names any emulator-free gate missing from `ci_portable.txt`/`ci_static.txt`. Emulator gates and soaks stay manual, indexed in HANDOFF.
- [VSP-102] **Close stdin when looping a gate list** (`</dev/null`) — a gate that reads stdin swallows the rest of the list, and a 32-entry run silently became 28; "not portable" gates need ROMDIR, a build dir or a binary and would SKIP on a clean checkout.
- [VSP-103] **A gate that is not in the battery can sit FAILING for sessions** — when a freeze changes design semantics, grep `tests/` for every gate touching the changed surface and run them BEFORE closing; a red gate nobody runs reads as "regression" to whoever finally runs it.
- [VSP-104] **A self-test's deliberate FAIL must never write into the shared evidence path** — stubbed failures preserved to `build/gate_failures/` for a week presented as a post-close gate failure; fixtures point `M2A_KEEP_DIR` at their own workdir.
- [VSP-105] **Propagate a builder's status: redirect, never pipe through `tail`; and assert the rompath exists before measuring it** — a rejected artifact was on disk before the rejection, and a chained `-rompath "dir;$ROMDIR"` resolves the PRISTINE set when the build dir is empty, measuring vanilla against vanilla (`tests/test_build_gate_status.sh`).
- [VSP-106] **A rompath is a SEARCH PATH — name the set you actually built** — `build_fingerprint.py` without `--set` fell through to `$ROMDIR` and reported the pristine ROM's fingerprint as a WIDE build's; a fingerprint equal to a known reference row is a bug until proven otherwise.
- [VSP-107] **`BUILD=... tests/<gate>.sh` is SILENTLY IGNORED by positional-arg gates** — half the suite reads `${BUILD:-}` and half `${1:-}`; grep the gate's BUILD= line before quoting any per-build result, and when a differential comes out identical check that the variable was varied.
- [VSP-108] **Canonicalise every path argument at the top and print the resolved fingerprint of what was actually opened** — a repo-relative check with an absolute build dir let MAME fall through to `$ROMDIR` and label pristine vanilla with the build's name; a verdict control that CRASHES reads as a control that fired, so distinguish "rejected" from "died".
- [VSP-109] **A gate must not depend on the caller's environment** — a relative `ROMDIR` failed two gates that resolve from another cwd; python blocks take paths as ARGV, not inherited env; run a new gate's first pass under `env -i`; printed identifiers a human might compare across runs must be stable digests, never `hash()`.
- [VSP-110] **The shell traps that fail silently and leave a plausible result** — backticks inside double quotes are command substitution (write bodies to a file, `--body-file`); `VAR=x funcname` PERSISTS after a shell function; `grep -vxF "$multiline"` matches everything if any line is blank (diff files); `git tag -l | tail` sorts LEXICALLY (`git rev-parse --verify` the tag you mean); never edit a running `.sh` (sh reads by byte offset — copy and run the copy).
- [VSP-111] **awk compares hex fields as NUMBERS when they look numeric, and macOS awk has no `and()`/`strtonum()`** — normalise widths in the shell and force string comparison; never use gawk builtins in this repo's gates (python3 is already a dependency); a shell `if` on an exit status treats a CRASH as the false branch, so capture the value and compare it.
- [VSP-112] **`grep -c ... || echo 0` double-prints on zero, and a `|| fallback` after a pipeline reads the LAST command's status** — `n="$(grep -c ...)" || true`; guard the FILE (`[ -s "$f" ]`) not the pipeline; ABSENT, ZEROS and a value are three outcomes.
- [VSP-113] **A worktree branches from a STALE `origin/main`** — `git reset --hard main` immediately after creating one, `git worktree prune` after a path change, commit before anything that moves the tree; rompath overlays are ABSOLUTE symlinks into `$ROMDIR` and dangle on a rename; any measurement to be quoted records the tooling commit.
- [VSP-114] **A verdict line may state only what its OWN branch measured** — a PASS message restating a control's conclusion kept printing under a dead control; gate any restatement on the control's result, and grep success messages that describe another section's measurement.
- [VSP-115] **A two-leg A/B that bails on leg 1 leaves leg 2's health an ASSUMPTION** — run the reference leg anyway and print MERGE-SPECIFIC vs LATENT IN THE FROZEN BUILD as part of the verdict; a covering gate that rebuilds at a different stage covers a DIFFERENT build.
- [VSP-116] **A pre-armed attribution is a hypothesis** — comments and headers may carry predictions; the printed verdict carries only what was measured, or points at the probe that measures it.
- [VSP-117] **The masked-basis canary corrupted the basis it verified** — an explicit `MAME_SANDBOX` is deliberate reuse, so clear a sandbox before every run unless nvram carry-over is the point (`tests/test_freeze_basis_sandbox.sh`); "the instrument control passed" is not "nothing moved" — `git status` the artifact after anything that can write it.
- [VSP-118] **`_PRG_RE` must match the WIDE extension members** — two builds differing only in extension content hashed identically until the suffix class included `.41-.44`; a fingerprint blind to a region is a fingerprint of a different artifact.

## D.5 Rigs, pokes and probes — the project's own instruments and how each has lied

- [VSP-119] **RECORD YOUR SESSION** — `WIDE_RECORD=<name> tools/run_wide.sh <build> mame` records a MAME `.inp` with a fresh named nvram start state; `WIDE_PLAYBACK=<name>` replays frame-exact on the same pinned binary against a throwaway nvram copy; FBNeo's SDL frontend has no equivalent, so record on MAME. A report with an `.inp` is a replay protocol any instrument can ride ([VSP-20]).
- [VSP-120] **Forced-pick pokes on `$FF8782`/`$FF8B82` end by ~frame 1500** — the early window 1400-1500 only; pokes held later leak into the SECOND player's load in the 2P flow (a whole "victim sweep" loaded as one id); a no-poke control verifies the flow.
- [VSP-121] **The forced pick does not populate the HUD index field** — in-match HUD stagers index a SEPARATE field only the real pick flow writes; verify HUD rows with the real-cursor replays (`36`/`37`/`40`, [MSV-28]), never the poke rig.
- [VSP-122] **The forced pick holds through SELECT only** — on a vs-CPU rig P2's loaded struct is rebuilt from the CPU's REAL pick, so `(0x382,P2) == my tenant` is true on 2P forced-pick replays and false on vs-CPU ones.
- [VSP-123] **The native leg is reachable for ANY tenant screen with the same poke** — force the tenant on `vsav2` (`POKES="1400:ff8782:10;..."`), poke BOTH sides when sprite lists are compared, and when the state under test is a MODE prove it was ENTERED (Dark Force: poke `$FF8509`, assert `$FF802E`=1 — never infer a mode from the fighter block). Do not characterise a tenant symptom without this leg.
- [VSP-124] **Rig grammar from the #103 hunt** — an opponent-class poke overlapping a LIVE match kills the match (window it BETWEEN matches from a prior no-poke run); repeated HP pokes across a KO un-KO the loser (kill pokes at round start +~100f, three pokes 20f apart, hands off); identify a screen from the STATE WORDS (`$FF8004/8008/800C`), never from banner text; before declaring RAM "frozen", diff a WIDE slice at two distant times past the longest plausible timeout.
- [VSP-125] **Kill/heal pokes write BOTH HP words** — the 2-byte shape leaves white HP positive and manufactures the unjudgeable round on any character (`tests/audit_kill_poke_shape.sh`); `GUARD_PROBE`'s `RET <(SP)>` is a caller only for jsr-reached code — use `GUARD_PROBE_HIST=N` for branch-reached callees; a `-debug` trace run carries its own `DUMPS` and is interpreted only against anchors from the SAME run.
- [VSP-126] **Probe ENTRY addresses, never the crash-line PC** — a group-0 exception pushes a mid-instruction PC no breakpoint can match, and a probe PC inside an operand measures NOTHING while looking green; compute a farm entry from the FARM BASE, and demand a must-fire control at the SITE under the rig's own conditions (a plausible site can be dead code; a control site can be unreachable under the pokes).
- [VSP-127] **One dump directory per rig iteration, one LOG directory per leg** — `DUMPS` land beside `CHECKSUM_OUT` as `dump_<frame>_<addr>.bin`, so shared directories silently overwrite evidence and reassign one leg's dumps to another; the sandbox argument has nothing to do with it.
- [VSP-128] **`DUMPS` windows are `;`-separated** — a comma-joined spec exits rc=3 after a full boot with no artifacts and no error text.
- [VSP-129] **Cross-build A/B dumps run PROBE-FREE** — debugger overhead lands at different instruction boundaries on two builds and phase-shifts an animation per leg (a persistent 23-byte "diff" that was zero clean); find the address under a probe, then re-run the A/B with taps or plain `DUMPS`.
- [VSP-130] **`-debug` fire counts do not transfer to checksum timelines** — on collision-sensitive content the debug timeline plays a different match; attribute a moved baseline with `DUMPS=<frame>:ff0000-ffffff` on BOTH builds at a divergent frame and diff the bytes.
- [VSP-131] **A scripted motion input is NOT the move you named** — the buffer folds leading directions, scripted strengths are not authoritative, and a special's button press must OVERLAP the final direction frames; identify an activated move by measured EFFECTS (stock cost, seq id, spawned objects, the screen) and send disagreeing captures to the maintainer before building on the identification.
- [VSP-132] **A 1P-arcade rig is silently pinned to the ARCADE DRAW** — any timing change re-rolls its opponent and stage, so a frozen fight-derived value describes a fight nobody's build has run; PIN the opponent (2P + early-window pokes) and, when a frozen-value audit goes red, check WHICH match it measured before how the fight went.
- [VSP-133] **A fixed-frame rig verified on ONE character whiffs on another** — reach, knockdown arcs, down windows and wake timing are per-character on BOTH sides; a multi-character audit measures (input, frame) pairs per leg and its checker REFUSES to judge a leg whose setup event did not happen.
- [VSP-134] **An entry-set A/B needs a QUIET-FRAME presence profile** — an entry present far from the event is scenery (the stock-meter pips read as beam segments and cost a window session its first hours).
- [VSP-135] **Cross-emulator POSITION A/B compares RELATIVE offset, never absolute x** — the two builds sit at a fixed ~21px global shift; `p2 − p1` was 42 on both legs while absolute x "proved" the rig incomparable; pre-event agreement is the free positive control.
- [VSP-136] **Cross-game pixel A/B aligns by DISPLAYED RECORD, not frame** — the engines skew 1-2 frames, so same-frame snapshots compare different anim records; align on the victim's cursor value, and remember the sibling games' VANILLA characters have differing script data.
- [VSP-137] **A soak must assert the mechanism it exists to exercise fired** — scripted ES pairs silently fell back to LP while the DP-spam gate stayed green on END-clean; and a hit-path defect fires per COLLISION, not per frame, so pair a soak with a FIRE CENSUS on the dispatcher.
- [VSP-138] **Validate a fix against the reporter's EXACT input and A/B fix-on/fix-off on the reproducing replay** — snapshot every phase of a cyclic effect; "the metric improved" is not "the pixels changed".
- [VSP-139] **Verify at the RENDER layer before believing the RAM layer** — `tests/lua/obj_records_dump.lua` + `snapshot_frames.lua` (both `POKES`-capable) answer "is it on screen?" in one run; correct-looking writes on the ONE object you watch say nothing about objects never spawned. Reach for them before the third RAM-layer iteration.
- [VSP-140] **The masked checksum samples EARLIER in the frame than dumps do, and unmasked per-frame checksums PERTURB the run** — inspect a masked-gate divergence at the checksum's sample point (or diff checksum halves, then trace writes); legacy comparisons replicate the gate's exact mask set, and mixed-mask runs are not comparable.
- [VSP-141] **A RENDER verdict from a gfx-free build is VOID** — the program-over-zero-overlay pack answers RAM questions only; palette/work-RAM dumps are gfx-free-safe, pixels are not.
- [VSP-142] **Resolve `placements.json` regions PER TENANT** — a lookup hardcoding `anim` mapped two tenants through the wrong dst/src and published a false mismatch that shaped a fix design; "the delta differs per tenant" is a smell about the mapping before it is a finding about the game.
- [VSP-143] **A cited address in a session log is a CLAIM** — grep the manifest row AND `xxd` the built image at the call site before building a theory on it; one misread hex digit cost a session plan and survived two summaries.
- [VSP-144] **A pool measurement is a claim about ONE pool** — decode the dispatch walker's own base+stride from the opcode view before trusting that a slot-level fact transfers to a family; two pools shared a layout and the census numbers looked healthy.
- [VSP-145] **A0-at-write is post-increment** — subtract the movem batch size from EVERY logged value before taking min/max of a read window; the misread placed a fix on dead ground for a playtest round.
- [VSP-146] **A same-slot "vanilla control" controls nothing** — to test "is X per-char?", the control varies the CHARACTER, not just the build.
- [VSP-147] **The `-debug` write-trace never disagreed with the non-debug dumps** — a MAME watchpoint logs REGISTERS, so a "value written" quoted from a trace is a table lookup that must name WHICH IMAGE it read; grep `patch.json` for the table's range before declaring it unpatched; when in doubt take the non-debug tap (`FBNEO_HTAP`).
- [VSP-148] **A measurement returning a clean null is a bug report about the measurement** — capstone mnemonics carry a size suffix (compare on the stem); a register-dataflow walk cannot see a mask applied in place to memory (enumerate the ADDRESSING MODES that can touch the value); two agreeing methods sharing a premise are one method.
- [VSP-149] **Half the Lua instruments stage inputs one frame off `replay.lua`** — every divergence-attribution instrument is canonical, the probe family is one frame early; never cross-reference a frame number between instruments; the split is frozen at 10/11 by `tests/test_replay_stage_census.sh` (strip Lua comments before classifying), the fix is deferred WITH the re-derivation of five gates' constants, and when it lands re-freeze nothing.
- [VSP-150] **THE OUT-OF-RANGE INDEX TOOLKIT: read the CONSEQUENCE before valuing any evidence** — `audit_index_space.py` names the danger windows, `audit_index_users.py` says which tenant data lands in one (reports, never filters), `index_watch.lua` attributes a live dispatch to the MOVE (prove it with `INDEX_ALL=1` before trusting quiet); "no crash" clears a LOUD entry completely and a SILENT one not at all.
- [VSP-151] **The DF palette-seq block census is MEASURED, never derived from the request table** — the routine is conditional; the resolver masks to 12 bits so a tenant block must sit inside the vanilla range and cannot go in `wide_ext`; `CHARS=... tests/audit_palette_seq_ids.sh`.
- [VSP-152] **The M2a debug environment on `run_replay_guarded.sh`** — `GUARD_PROBE=<pc>` [+`GUARD_PROBE_COND`] is a conditional LOGGING breakpoint (regs + (SP), run continues), `GUARD_TRACE`, `GUARD_PC_LOG`, `GUARD_BREAK`, `GUARD_MATCH`; faults log `CRASH` + `REGS` + `STACK` and dump work RAM; `MASK_RANGES` on `replay.lua` selects the live-state basis, unset means canonical whole-RAM checksums.

## D.6 Attribution — how a wrong conclusion was reached, and the cheaper method

- [VSP-153] **A symptom grouping is a HYPOTHESIS — test it member by member, cheapest first** — write "possibly one root", ask what measurement would DISTINGUISH the members, and check the cheap member (one playtest) before the expensive one; never carry a filter (palette, bank, code range) across effects; look at a capture before sending it.
- [VSP-154] **Cross-build A/B is the cheapest attribution and is routinely skipped for analysis** — every kept build plays via `tools/run_hui_behavior.sh <build>`; bisect the BUILDS before analysing the code; the launcher refuses to rebuild into an existing directory so a pruned rompath is never silently refilled.
- [VSP-155] **PRIOR ART FIRST** — before porting a per-character subsystem for tenant B, read that subsystem's `engine_internals.md` section and diff tenant A's manifest rows against what you are about to write; a maintainer's "this looks like the thing we fixed for X" is a high-confidence pointer, not a hypothesis; a check that is self-labelling beats one that only proves internal consistency.
- [VSP-156] **A REPLAY'S NAME IS A CLAIM ABOUT THE BUILD** — an artifact whose meaning depends on the build needs asserting like any instrument constant ([MSC-52]); the expectation class and the gate that names the replay in words are the cheap assertions; consult them before scoping a measurement on a filename.
- [VSP-157] **Root-causing a stochastic crash: determinism first, vector+address second, history third, conditional register probe last** — keep ANY deterministic repro as the lab rat (contamination matters for the PATH, not the mechanism), read the fault address's parity, `GUARD_PROBE_HIST` for the stream, then a probe conditioned on the faulting register value; extend the instrument the moment it cannot name what you need.
- [VSP-158] **Never chain "the fix" from a poke-contaminated mechanism when a field recording exists** — win-fast rigs never give a CPU opponent's AI time to reach its rarer scripts; the first natural-path capture beat two shipped fixes ([VSP-20], [VSP-71]).

## D.3b Sprite lists and their art (the porting_sprite_lists method)

- [VSP-159] **The four questions of any ported effect, in order** — does the host have the CLASS row (vsav ships some effect-class rows as stubs; port the handler family and `[[code_ptr]]` the row — a `code` op, never `poke32`, and the row must be dead in vanilla with a positive control); does it have the LIST TYPE (the drawer table can neither grow nor move — take over a type dead in vanilla with a `jmp` and retype the tenant's lists, discriminating on an ADDRESS RANGE with the host's original code as fallback and a tripwire a gate keeps at zero; never repoint a type whose handler is a bare `rts`, legacy dispatches it thousands of times); does the handler carry a game-specific CONSTANT (the per-handler code bias differs between the games — port a copy with the SOURCE bias plus the placement shift); where does the art's BANK come from (some types read the object's bank word, one hardcodes bank 1 — a character's effects may draw from more than one bank).
- [VSP-160] **Strip placement: inventories are SPANS, not samples** — the `--strip-tiles` shift must be 16-aligned, equal to the bias baked into the ported handler (one number in two places, a gate freezes both), below the frozen ceiling and clear of the tenant's band, and never into the host's own bank 1 (measured occupied); take the whole span of the effect's family, because sampling native and sampling ours both missed strips.
- [VSP-161] **The order of work and the check at each step, ending with LOOKING** — class row (`test_hui_boot.sh` legacy EXACT), list-type takeover (`test_beam_list_type6.sh`, `audit_effect_class_rows.sh`), ported handler, tile span (`audit_empty_tiles.sh` ON THE EFFECT'S OWN REPLAY — its defaults never fire the effect and pass vacuously), then snapshots against native at matched frames; step 4 does not replace step 5, since real-but-wrong tiles pass the empty-tile audit at full opacity.
